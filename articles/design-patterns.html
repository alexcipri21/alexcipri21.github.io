1. Creational Patterns (Object Creation)

// SINGLETON
// Ensures a class has only one instance and provides a global access point
public class DatabaseConnection {
    private static DatabaseConnection instance;

    private DatabaseConnection() {} // Private constructor prevents instantiation

    public static synchronized DatabaseConnection getInstance() {
        if (instance == null) {
            instance = new DatabaseConnection();
        }
        return instance;
    }
}

// FACTORY METHOD
// Defines an interface for creating an object, but lets the factory decide which class to instantiate.

interface Notification { void send(String msg); }
class EmailNotification implements Notification { public void send(String msg) { /* ... */ } }
class SMSNotification implements Notification { public void send(String msg) { /* ... */ } }

class NotificationFactory {
    public static Notification createNotification(String type) {
        if ("EMAIL".equalsIgnoreCase(type)) return new EmailNotification();
        if ("SMS".equalsIgnoreCase(type)) return new SMSNotification();
        throw new IllegalArgumentException("Unknown type: " + type);
    }
}
}

📌 Singleton

  • Ce face: Garanteaza ca exista o singura instanta a unei clase in intreaga aplicatie si ofera un punct global de acces la ea.
  • Unde se folosește: Conexiuni la baze de date, app config, servicii de logging.
  • Cheie: Constructor private (sa nu poata fi apelat din exterior) + metoda static pentru instantiere.

📌 Factory Method

  • Ce face: Deleaga crearea obiectelor catre o metoda dedicata, decupland codul principal de clasele concrete.
  • Unde se folosește:
    • Cand o clasa nu poate anticipa tipul exact de obiecte pe care trebuie sa le creeze la runtime.
    • Cand vrei ca subclasele sau fabrica sa specifice logica de creare.
    • Cand vrei sa ascunzi un proces complex de inițializare.
    • Cand vrei sa adaugi tipuri noi de obiecte mai tarziu fara sa modifici codul existent.
  • Cheie: Nu folosesti operatorul new direct in codul principal pentru a crea un obiect, ci apelezi o metoda care creeaza si returneaza obiectul.

2. Structural Patterns (Relationships Between Entities)

// ADAPTER
// Allows incompatible interfaces to collaborate
interface TypeC { void chargeWithTypeC(); }
interface MicroUSB { void chargeWithMicroUSB(); }

class MicroToTypeCAdapter implements TypeC {
    private MicroUSB microUsbDevice;

    public MicroToTypeCAdapter(MicroUSB device) { this.microUsbDevice = device; }
    
    @Override
    public void chargeWithTypeC() {
        microUsbDevice.chargeWithMicroUSB(); // Converts interface call
    }
}

// DECORATOR
// Dynamically attaches new responsibilities to an object without altering its structure
interface Coffee { double getCost(); }
class SimpleCoffee implements Coffee { public double getCost() { return 5.0; } }

class MilkDecorator implements Coffee {
    private Coffee coffee;
    public MilkDecorator(Coffee coffee) { this.coffee = coffee; }
    public double getCost() { return coffee.getCost() + 1.5; }
}

📌 Adapter

  • Ce face: Traduce interfata unei clase intr-o alta interfata pe care o asteapta clientul (ex. un adaptor fizic de priza sau cablu).
  • Unde se folosește: Când vrei să integrezi librarii third-party sau cod legacy fara sa modifici interfetele lor existente.
  • Cheie: Clasa adaptor impacheteaza obiectul incompatibil si apeleaza intern metodele acestuia.

📌 Decorator

  • Ce face: Adauga functionalitati noi unui obiect in mod dinamic, la runtime, fara a modifica clasa originala sau a folosi mostenire excesiva.
  • Unde se folosește: I/O Streams din Java (BufferedReader(new FileReader(...))), sisteme de optiuni/extra-costuri (ex. cafea + lapte + sirop).
  • Cheie: Decoratorul implementeaza aceeasi interfata ca obiectul decorat si pastreaza o referinta catre acesta.

3. Behavioral Patterns (Communication Between Objects)

// STRATEGY
// Defines a family of algorithms, encapsulates each one, and makes them interchangeable
interface PaymentStrategy { void pay(int amount); }
class CreditCardPayment implements PaymentStrategy { public void pay(int amount) { /* ... */ } }
class PaypalPayment implements PaymentStrategy { public void pay(int amount) { /* ... */ } }

class ShoppingCart {
    private PaymentStrategy paymentMethod;
    public void setPaymentMethod(PaymentStrategy strategy) { this.paymentMethod = strategy; }
    public void checkout(int amount) { paymentMethod.pay(amount); }
}

// OBSERVER
// Subscription mechanism to notify multiple objects about any events
interface Observer { void update(String msg); }
class User implements Observer { public void update(String msg) { /* Notify user */ } }

class Newsletter {
    private List<Observer> subscribers = new ArrayList<>();
    public void subscribe(Observer o) { subscribers.add(o); }
    public void notifySubscribers() {
        for(Observer o : subscribers) o.update("New Article!");
    }
}

📌 Strategy

  • Ce face: Defineste o familie de algoritmi, ii izoleaza în clase separate si ii face interschimbabili la runtime.
  • Unde se folosește:Cand e nevoie de algoritmi care au implementari diferite.
  • Cheie: Evită evita if-else sau switch folosind strategia ca parametru.

📌 Observer

  • Ce face: Defineste un mecanism de abonare (Publish/Subscribe) pentru a notifica automat mai multe obiecte cand are loc un eveniment.
  • Unde se folosește: Event Listeners în UI (click events), sisteme de notificare (push notifications, newsletter), arhitecturi Event-Driven.
  • Cheie: Subiectul menține o listă de subscribers si ii parcurge cu o bucla cand trimite notificarea.
